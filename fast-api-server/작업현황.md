# 작업 현황

## 1. 현재까지 완료한 작업

### 아키텍처

- Spring Boot / Redis 와 FastAPI / MediaMTX를 분리하는 2-EC2 구조 확정
- 두 EC2는 같은 VPC 안에서 `private IP`로 통신하도록 설계

### FastAPI

- 내부 제어 API 구현
  - `POST /api/stream/start`
  - `POST /api/stream/stop`
  - `GET /api/stream/{broadcast_id}/status`
- `broadcast_id + stream_key` 기반으로 입력/출력 경로 자동 계산
- MediaMTX RTSP pull 기반 프레임 처리 구현
- Redis 메타데이터 조회 구현
- FFmpeg 기반 HLS 파일 생성 구현
- `/hls/{broadcast_id}/index.m3u8` 정적 서빙 구현
- `focus-server`와 예외 응답 포맷 통일
- 배포용 Dockerfile / GitHub Actions / EC2 compose 초안 작성
- 배포 환경 `.env`에 불필요한 값이 들어와도 서버가 죽지 않도록 `Settings`에 `extra=\"ignore\"` 반영

### Spring Boot

- 방송 시작 시 FastAPI `/api/stream/start` 자동 호출 구현
- 방송 종료 시 FastAPI `/api/stream/stop` 자동 호출 구현
- FastAPI가 반환한 `hlsUrl`을 방송 엔티티에 저장하도록 구현
- `StartBroadcastRequest`를 `avatarId` 기준으로 정리
- 로컬 E2E 문서 및 로컬 JWT 발급 스크립트 정리

### 인프라 / AWS

- Spring + Redis EC2 확인 완료
- FastAPI + MediaMTX용 신규 EC2 생성 완료
- 보안 그룹 설정 완료
  - Spring EC2 -> FastAPI EC2 `8000/tcp`
  - FastAPI EC2 -> Redis `6379/tcp`
  - 외부 -> MediaMTX `8890/udp`
  - 외부 -> FastAPI `8000/tcp`
- FastAPI EC2에 Docker / Docker Compose 설치 완료
- FastAPI 수동 배포 완료
- Spring 수동 배포 완료

## 3. 현재 운영 방식

- 스트리머 클라이언트 -> MediaMTX: `SRT publish`
- 스트리머 클라이언트 -> Spring: 인증 / 방송 API / gRPC 메타데이터 / heartbeat
- Spring -> FastAPI: 방송 start / stop / status 내부 호출
- FastAPI -> MediaMTX: `RTSP pull`
- FastAPI -> Redis: `broadcast:{broadcast_id}:meta:{pts_us}` 조회
- 시청자 클라이언트 -> Spring: 방송 목록 / 상세 조회
- 시청자 클라이언트 -> HLS URL: `.m3u8` 재생

## 4. 다음 주 작업 예정

### 1) HLS 저장소 구조 개선

현재는 FastAPI 로컬 디스크에 HLS를 생성하고 직접 서빙합니다.

다음 주 검토/구현 대상:

- S3 업로드 구조
- CDN 연동 구조
- `hlsUrl`을 FastAPI 직접 URL이 아니라 CDN URL로 전환

검토 포인트:

- 현재처럼 파일 생성 직후 바로 재생 가능한지
- `.m3u8` / `.ts` 업로드 지연 허용 범위
- 캐시 무효화 전략
- CloudFront 또는 다른 CDN 연결 방식

### 2) FastAPI 종료 상태 정리

현재 짧은 테스트 스트림이 끝나면 워커 상태가 `failed`로 남습니다.

다음 주 작업 후보:

- 입력 스트림 종료를 정상 종료로 간주
- `failed` 대신 `stopped` 또는 별도 `completed` 상태 처리

### 3) GitHub Actions CI/CD 마무리

해야 할 일:

- 두 레포 GitHub 시크릿 등록
- `main` 머지 후 자동 배포 검증
- 배포 실패 시 로그 확인 플로우 정리

### 4) 모델 연동

- `model/renderer.py`에 실제 아바타 합성 모델 이식
- 메타데이터 미수신/품질 저하 시 블러 fallback 정책 구체화
- GPU 인스턴스 필요 여부 검토

## 5. 결정 사항 메모

1. 장기적으로 FastAPI와 Spring은 같은 EC2에 두지 않는다.
2. FastAPI는 나중에 모델이 붙을 가능성이 높아서 별도 EC2로 운영한다.
3. 현재 단계에서는 HLS를 S3로 보내지 않고 로컬 디스크 기반으로 먼저 검증한다.
4. S3 + CDN 전환은 다음 주 작업으로 넘긴다.
