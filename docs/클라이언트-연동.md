# 클라이언트 연동 문서

이 문서는 현재 구조 기준으로 스트리머 앱과 시청자 앱이 어떤 순서로 서버와 연동해야 하는지 정리한 문서입니다.

## 1. 전체 흐름

### 스트리머 앱

1. Spring 인증 완료
2. Spring에 방송 생성 요청
3. 응답으로 `broadcastId`, `streamKey` 수신
4. MediaMTX로 SRT 영상 publish 시작
5. Spring gRPC로 얼굴 메타데이터 전송 시작
6. Spring에 방송 시작 요청
7. Spring이 FastAPI 워커를 자동 시작
8. FastAPI가 HLS 생성
9. Spring 응답 또는 방송 상세 조회에서 `hlsUrl` 확인
10. 방송 중에는 streamer heartbeat 전송
11. 종료 시 Spring에 방송 종료 요청

### 시청자 앱

1. Spring에서 방송 목록/상세 조회
2. `status=ON_AIR` 인 방송의 `hlsUrl` 획득
3. HLS 플레이어로 재생
4. 시청 중에는 viewer heartbeat 전송

## 2. 역할 분리

### 클라이언트가 직접 붙는 대상

- Spring Boot
  - 인증/인가
  - 방송 생성/시작/종료
  - 방송 목록/상세 조회
  - 하트비트
  - gRPC 얼굴 메타데이터 수신
- MediaMTX
  - 스트리머 영상 ingest

### 클라이언트가 직접 붙지 않는 대상

- FastAPI
  - Spring이 내부적으로만 호출
  - 클라이언트가 `/api/stream/start`, `/stop`, `/status`를 직접 호출하지 않음

## 3. 스트리머 앱 연동 순서

## 3-1. 방송 생성

요청:

```http
POST /api/v1/broadcasts
Authorization: Bearer <token>
Content-Type: application/json
```

예시 바디:

```json
{
  "title": "오늘의 방송"
}
```

응답 핵심 필드:

```json
{
  "success": true,
  "data": {
    "broadcastId": "01KN1P9YE7W07WJSH2H4KFAWR2",
    "streamKey": "d7963ec1-3f1d-4eb1-8b38-4be32742d717",
    "status": "READY"
  }
}
```

클라이언트는 여기서 받은 값을 저장합니다.

- `broadcastId`: 방송 식별자
- `streamKey`: MediaMTX publish path 식별자

현재 AWS 운영 기준 MediaMTX 접속 호스트:

- `mediaMtxHost = 13.125.126.120`

## 3-2. SRT 영상 송출

스트리머 앱은 MediaMTX로 영상을 SRT로 송출합니다.

형식:

```text
srt://<MEDIAMTX_HOST>:8890?streamid=publish:live/<streamKey>
```

예시:

```text
srt://13.125.126.120:8890?streamid=publish:live/d7963ec1-3f1d-4eb1-8b38-4be32742d717
```

정리:

- 프로토콜: `SRT`
- 포트: `8890/udp`
- path prefix: `live`
- path key: 방송 생성 시 받은 `streamKey`
- AWS 운영 기준 host: `13.125.126.120`

## 3-3. 얼굴 메타데이터 gRPC 전송

Spring gRPC 서비스:

- package: `focus.metadata.v1`
- service: `FaceMetadataIngestService`
- rpc: `PushFaceMetadata(stream PushFaceMetadataRequest)`

중요 필드:

| 필드 | 설명 |
|---|---|
| `session_id` | `broadcastId`를 넣습니다 |
| `pts_us` | 영상 프레임과 같은 기준의 PTS 마이크로초 값 |
| `faces` | 현재 프레임의 얼굴 목록 |

예시:

```json
{
  "sessionId": "01KN1P9YE7W07WJSH2H4KFAWR2",
  "ptsUs": 133333,
  "faces": [
    {
      "trackingId": 0,
      "bbox": {
        "x": 659,
        "y": 177,
        "width": 49,
        "height": 64
      },
      "tdmmRaw": {
        "coeffs": [0.12, -0.05, 0.0, 0.03]
      }
    }
  ]
}
```

중요 규칙:

- `session_id`는 현재 방송의 `broadcastId`
- `pts_us`는 영상과 같은 타임라인을 따라야 함
- FastAPI는 Redis에서 `broadcast:{broadcast_id}:meta:{pts_us}` 키로 메타데이터를 읽음

## 3-4. 방송 시작

스트리머 앱은 SRT 송출과 gRPC 전송이 준비된 뒤 Spring에 방송 시작을 요청합니다.

요청:

```http
POST /api/v1/broadcasts/{broadcastId}/start
Authorization: Bearer <token>
Content-Type: application/json
```

예시 바디:

```json
{
  "avatarId": "avatar_001"
}
```

설명:

- 이 API를 호출하면 Spring이 FastAPI 내부 API를 호출합니다.
- `avatarId`는 Spring PostgreSQL `avatar.avatar_id`와 일치해야 합니다.
- Spring은 `avatar.object_key`를 조회해 FastAPI에 `avatar_asset_key`로 전달합니다.
- FastAPI는 해당 S3 prefix/zip을 로컬 캐시에 내려받아 합성에 사용합니다.
- FastAPI는 내부적으로 `rtsp://<mediamtx>/live/{streamKey}`로 읽기 시작합니다.
- 성공하면 Spring 응답의 `data.hlsUrl`에 재생 가능한 HLS 주소가 들어옵니다.

## 3-5. 방송 중 heartbeat

스트리머 앱:

```http
POST /api/v1/broadcasts/{broadcastId}/streamer-heartbeat
Authorization: Bearer <token>
```

권장 주기:

- 10초 간격

## 3-6. 방송 종료

요청:

```http
POST /api/v1/broadcasts/{broadcastId}/stop
Authorization: Bearer <token>
```

설명:

- Spring이 방송 상태를 `ENDED`로 바꾸고
- 내부적으로 FastAPI 워커 중지 API도 호출합니다.

## 4. 시청자 앱 연동 순서

## 4-1. 방송 목록 / 상세 조회

사용 API:

- `GET /api/v1/broadcasts`
- `GET /api/v1/broadcasts/{broadcastId}`

시청자는 여기서 다음 값을 봅니다.

- `status`
- `title`
- `memberName`
- `hlsUrl`

`status=ON_AIR` 이고 `hlsUrl`이 존재하면 재생 가능 상태입니다.

## 4-2. HLS 재생

예시:

```text
http://13.125.126.120:8000/hls/01KN1P9YE7W07WJSH2H4KFAWR2/index.m3u8
```

플레이어 예시:

- Android: ExoPlayer
- iOS: AVPlayer

현재 구조에서는 HLS를 FastAPI가 직접 서빙합니다.

## 4-3. 시청자 heartbeat

요청:

```http
POST /api/v1/broadcasts/{broadcastId}/heartbeat
Authorization: Bearer <token>
```

권장 주기:

- 10초 간격

## 5. 현재 연동 기준값

### 로컬 개발

- Spring: `http://127.0.0.1:8080`
- FastAPI: `http://127.0.0.1:8000`
- MediaMTX SRT publish: `srt://127.0.0.1:8890?streamid=publish:live/{streamKey}`

### AWS 현재 기준

- Spring public: `http://3.35.202.126:8080`
- FastAPI public HLS: `http://13.125.126.120:8000/hls/{broadcastId}/index.m3u8`
- MediaMTX SRT publish: `srt://13.125.126.120:8890?streamid=publish:live/{streamKey}`
- MediaMTX host: `13.125.126.120`
- Spring -> FastAPI 내부 호출: `http://172.31.38.193:8000`
- FastAPI -> Redis 내부 연결: `redis://172.31.38.55:6379/0`

## 6. 주의사항

1. 스트리머 앱은 FastAPI를 직접 제어하지 않습니다.
2. `streamKey`는 영상 송출용이고, `broadcastId`는 방송/메타데이터 식별용입니다.
3. `pts_us`는 영상 프레임 PTS 기준이어야 합니다. FastAPI가 작은 마이크로초 단위 오차는 보정하지만, 클라이언트가 별도 wall-clock 기준으로 보내면 fallback 처리될 수 있습니다.
4. 현재 HLS는 FastAPI 로컬 디스크 기반입니다.
5. 추후 S3 + CDN 구조로 바뀌면 시청자 앱은 `hlsUrl`만 그대로 쓰면 됩니다.
